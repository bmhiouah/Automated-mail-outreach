# 2026-10-05

## CVs tab — variant list UX (recompile on click, base listed, delete)

Worked on the CVs tab of the cold-approach tracker.

Changes:
- `app/latex_build.py`: new `remove_variant_files(vid, pdf_path=None)` — deletes a
  variant's `data/cvs/cv-<id>.tex`/`.pdf`, refuses any path resolving outside
  `CV_DIR`, best-effort (never raises).
- `app/api/cvs.py`: new `api_cv_delete` + `POST cvs/delete` route. Refuses the base
  (id 0) and any variant an **unsent** `mail_queue` row points at (a NULL cv_id would
  let the draft send with no attachment, silently). A variant only a `sent` mail used
  may be deleted.
- `web/app.js`: clicking a variant row now recompiles it before showing the PDF
  (`recompileAndShow`), so a saved edit is always reflected. Base (id 0) is compiled
  on demand by `/api/cvs/base-pdf`, so loading it already is the recompile. Added
  `cvBusy` guard (one pdflatex at a time), `revealPreview()` scrolls the preview into
  view, and `deleteCv(ev, id)` + a Delete button per row (hidden for the base,
  `stopPropagation` so the row's open handler does not fire).
- The base `main.tex` is already returned first by `api_cv_list` as id 0 — it was in
  the code but the user's running server predated it, which is why they had not seen it.
- Docs: README "The CVs tab" + ARCHITECTURE "Tests" updated.

## Important gotcha found (and fixed)

`tests/test_cvs.py` writes/deletes compiled CVs, but `latex_build.CV_DIR` points at
the **real** `data/cvs/`. The first run of the new delete tests therefore deleted two
real PDFs (`cv-1`, `cv-3`) — the test DB is a temp DB, but the *files* are not.
Fixed by pointing `latex_build.CV_DIR` at a temp dir for the whole module
(`setUpModule`/`tearDownModule`), with a `real_cv_dir()` context manager for the two
pre-existing tests that must read the real `main.pdf`. Both deleted PDFs were restored
by recompiling from the LaTeX stored in `cv_variants.latex`.

Lesson for this project: any test touching a module-level output directory must
repoint that directory, not just the database.
