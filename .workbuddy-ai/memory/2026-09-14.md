## Project kickoff — cold approach tool for quant finance job search

**User context (locked in this session)**
- Job hunting in quantitative finance: quant trading, trading, structuring, quant, algo trading.
- Target geography: **Paris + London**.
- Experience level: **0–2 years**.
- Firm types wanted: banks (S&T/structuring), hedge funds, prop trading & HFT, asset managers,
  commodities, insurance AM (i.e. everything).
- Interface preference: **local web app** (chose it over Sheets/Notion).
- Working style: wants to build step by step with heavy feedback; wants a roadmap and good
  foundations first.

**Built (v1, foundations)**
- Stack: Python 3 stdlib only (no pip deps) + SQLite + vanilla JS single-file UI.
  Server on http://127.0.0.1:8765, launcher `run.sh`.
- `db/schema.sql`: companies, contacts, outreach, templates, profile, applications,
  pattern_evidence.
- `data/companies_seed.csv`: 273 firms (78 HF, 58 banks, 57 AM, 28 prop/HFT, 20 commodities,
  11 crypto, 10 insurance AM, 5 brokers, 6 other) with tier 1/2/3.
- `app/email_gen.py`: `{{placeholder}}` rendering, quality flags (missing hook, long body,
  unresolved placeholders), 4 default templates (quant / trading / structuring / follow-up).
- Email guessing: per-company `email_pattern` -> guess shown greyed in UI, never stored as fact.
- API: CRUD + `/api/generate`, `/api/import/contacts`, `/api/mark-sent` (+7d follow-up),
  `/api/stats`, `/api/export/contacts`.
- Smoke tested end to end: profile save -> contact import -> generate -> mark sent. Test data
  cleaned afterwards (DB is empty except companies + templates).

**Decisions / conventions**
- Guess vs verified is a hard distinction: `email_status` unknown|guessed|verified|bounced.
- One follow-up only, +7 days, enforced by the UI.
- Every contact has a `hook` field — the personalisation line. No hook = generator flags it.
- Stdlib only, deliberately: no dependency install, works offline, user can read all code.

- **Scoring rule change**: `company_hook` now also satisfies the "no personalisation hook"

## Pass 7 — careers pages (found, not guessed)

**Why**: `careers_url` was 0/365 — a schema column nothing populated. The README itself
flagged it. Also the "Find people" button had no real destination.

**What shipped**
- `app/discover_careers.py` — crawls each firm's homepage, follows careers-looking links,
  falls back to common paths, and **only records a URL the server actually answered**.
  `--tier 1,2` / `--workers N` / `--limit N`.
- `data/careers_urls.csv` — **41 URLs, tier-1 complete**, columns
  `name,careers_url,http_status` (200 = verified, 403 = real but bot-blocked).
- `db.load_careers_urls()` — idempotent, writes only on change. Called from `server.main()`.
- `sourcing_links()` now returns the **real** careers page when known, plus
  `careers_search_url` (Google) and `careers_is_verified`. Falls back to the search when
  no page is known, so the button never opens a blank tab.
- UI: `Careers ↗` link per company row; `Brief` modal shows it too and now works for firms
  that have a careers URL but no brief.
- `tools.py brief` reports brief + careers coverage.

**The important lesson — the first crawler lied confidently**
The initial link heuristic matched link *text*, so it resolved:
  Bank of America → `/student-banking/`, BlackRock → `/corporate/home`,
  Morgan Stanley → `/people`, ExodusPoint → bare homepage, Optiver → a redirect token URL.
**Fix**: require the careers keyword in the URL **path** (`_path_ok`), not just the link
text. Dropped 29 "resolved" to a trustworthy subset, then I verified the rest by hand.
All five false positives are now regression tests in `TestCareersUrls`.

**Two real discoveries**
1. **Marshall Wace's domain is `mwam.com`, not `marshallwace.com`.** The seed was wrong,
   which is exactly why the crawler kept failing on it. Fixed in `companies_seed.csv`.
2. **ExodusPoint has no careers page on its marketing site** — it recruits through a
   Greenhouse job board (`job-boards.greenhouse.io/exoduspoint`). Added an `ATS_HOSTS`
   allowlist (Greenhouse, Lever, Workday, Ashby, iCIMS, Taleo, …) since those hosts are
   job boards by definition and carry no careers keyword in the path.
3. **AXA IM now redirects to `bnpparibas-am.com`** — confirms the AXA IM / BNP Paribas AM
   merger completed. Worth telling the user; the brief already flagged it as "in flux".

**403 is not a failure.** Citadel, Citadel Securities, BNP Paribas, UBS and QRT all return
403 to a script (bot firewall) — the URLs are correct. Recording the HTTP status lets the
user tell "verified" from "blocked" rather than losing those five.

## Pass 9 — the CV reader (attacking the actual blocker)

**Why**: the profile was empty because typing 16 fields is tedious, and *that* was the
thing blocking every downstream feature. Adding more company data was beside the point.

**What shipped**
- `app/cv_parse.py` — reads a pasted CV, proposes **17 profile fields**, and reports for
  each one **where it came from**. Stdlib only.
- `POST /api/parse-cv` → `{fields, evidence, missing, critical_missing, sections_found,
  confidence}`. Rejects text under 40 chars.
- Profile tab restructured: **1 · paste CV → read → review → fill the form**,
  **2 · profile card**. Extraction renders a review table with an evidence column; nothing
  is saved until the user presses Save. `applyCv()` fills the form fields.
- `renderGaps()` shows which critical fields are still empty after saving.
- `.txt` file loader via FileReader.
- `{{my_key_skills_short}}` (first 4) added to `build_context`; the three seed templates
  now use it, because 12 tools mid-sentence read as a wall of nouns. Re-seeded via
  `api_seed_templates()` (upsert by name) → 4 updated.
- Tests: **64 passing** (was 42).

**Design rule that mattered**: the parser proposes, it never saves, and it never invents.
Empty means "not found", and the UI says so. A CV is written by a human for a human;
anything claiming to parse one perfectly is lying, so the human reviews the table.

**Four bugs found while testing, all now regression tests**
1. **Phone regex required 2+ digit groups** → `+33 6 12 34 56 78` failed on the lone `6`.
   Loosened the pattern, then filtered on total digit count (9-15) which is what actually
   separates a phone from a date range. Also: `2018-2020` must NOT be a phone.
2. **`MONTH_RE` had capture groups** and was embedded in a larger pattern, shifting every
   group index — `years_exp` silently returned "". Split out a **non-capturing**
   `MONTH_TOKEN`. Lesson: never embed a capturing-group pattern inside another regex.
3. **Language vocabulary was English-only** → a French CV ("Français / Anglais / Espagnol")
   yielded nothing. Now a (canonical, [patterns]) table with FR/ES/DE spellings, and levels
   normalised too (`langue maternelle` → `native`), because the output feeds English templates.
4. **"shouting: MATLAB"** — the ALLCAPS check flagged every acronym. Added `OK_ACRONYMS`
   (~80 entries: tools, finance, places, titles). A checker that cries wolf trains you to
   ignore it, which is worse than not having it.
   Also capped `target_roles` at 2 with head-noun dedupe ("Quantitative Developer / Quant
   Developer" → one) since it is interpolated into a sentence.

**Verified end-to-end**: paste CV → 94% confidence, 0 critical gaps → save profile →
generate at Jane Street → **A-100, 95 words, no issues, no flags**, and the sentence reads
cleanly. All test data removed afterwards (profile name NULL, cv_text NULL, 0 contacts).

**Still waiting on user**: the CV itself. It is now a two-minute job rather than a chore.

## Pass 11 — contact capture (the blob problem)

The real bottleneck was never the mail, it was **getting people into the table**. We do not
scrape LinkedIn, so the user has to look — but what they get back is a blob, not CSV.

- New `app/people_parse.py`: paste any shape → reviewable candidates. Handles tabs, pipes,
  semicolons, dashes, commas, `Title at Company`, space-separated rows, bare names, and
  bare addresses. Strips `· 2nd` / `500+ connections` / `See more`, honorifics and
  credentials, keeps particles with the surname (`Willem de Vries`).
- Two-line LinkedIn profiles are stitched (`name` line + `Title at Company` line) and the
  location line below is absorbed as the city.
- Output is **propose-only**: every row carries a confidence and a plain-English `why`;
  rows under 0.6 arrive unticked; unreadable lines are listed with a reason, never guessed.
- `api_import_people()` saves the ticked rows, derives desk/seniority, and then runs
  `learn_patterns_from_samples()`. Ordering matters: the pattern matcher needs the contact
  to exist to match the address against, so learning runs **after** the inserts.
- A pasted address is stored `email_status='verified'`, `email_source='pasted'`, so the
  "fill empty emails from patterns" pass can never overwrite real evidence with a guess.
- `infer_pattern()` gained `min_confidence`: the paste path uses 0.85 so a bare address
  never silently becomes a firm's convention on a 0.5 shape guess. The manual
  "verify a pattern" button still applies everything (default 0.0).

**Five bugs, every one found by running realistic data rather than assuming**

1. **`_norm` collapsed tabs.** Tabs are the structural separator in a spreadsheet paste;
   collapsing `\s+` destroyed the columns and every row became one unparsable blob. Fixed
   with `[^\S\t]+` — whitespace except tab.
2. **`_strip_credentials` rebuilt the string with spaces**, so `Paris, Île-de-France, France`
   became `Paris Île-de-France France` — three capitalised words, no digits, no title
   keyword → `is_name()` said yes and **Paris became a person**. Fix: only rejoin when a
   credential was actually popped.
3. **Multi-word vocabulary was built with `.split()`**, so `"united kingdom"`, `"hong kong"`,
   `"new york"` shredded into single tokens and every location check quietly failed. Fix:
   define these as explicit phrase lists.
4. **Classification order.** `is_name("Jane Street")` is **True** — two capitalised words,
   no title keyword. Only the firm list can tell a person from a company, so the firm match
   must get first refusal. Reordered to company → name → location → title.
5. **The resolver is far too eager for this job.** Two traps: `Quantitative Developer
   Marshall Wace` resolves to Marshall Wace and eats the job title; and bare desk words
   resolve to firms — `trading` → Jump Trading, `research` → Qube Research, `portfolio` →
   IPM Informed Portfolio Management, `quantitative` → Quantitative Brokers. Fixed with a
   coverage rule: the firm's tokens must cover ≥75% of the chunk, and a **single-token chunk
   must match a single-token firm exactly**.

**Design rule this pass added**: *under-matching is fine, over-matching is silent and wrong.*
A firm we fail to recognise keeps its raw text and is flagged for review. A firm we wrongly
recognise corrupts the row without telling anyone. Every heuristic leans the safe way.

**Also**: a variable-shadowing bug in my own `renderPeople()` — the `COLS.map(col=>...)`
callback used `c` for the column tuple while `c` was also the candidate, so `c[c[0]]` read
the column's own property and every Firm cell rendered empty. Caught by reading the code
back, not by the syntax check. Renamed to `col`.

Tests: **94 passing** (was 72). New `TestPeopleParsing` (16) and `TestPasteImport` (6).
DB state unchanged after cleanup: 365 companies, 51 briefs, 83 careers pages, 4 templates,
0 contacts, 0 outreach, 0 pattern_evidence.
